一、游戏机制说明
================================================================================

  16×16 LED 矩阵显示的游戏画面:
  - 小车位于第 14-15 行(底部 2 行)，1 格宽
  - 小车通过 LEFT/RIGHT 按钮左右移动，列范围 0-15
  - 障碍物从第 0 行(顶部)自动下落，每个游戏时钟周期下降 1 行
  - 障碍物到达第 15 行时:
    若列位置与小车相同 → 碰撞，游戏结束(Game Over)
    若列位置不同 → 得分 +1，障碍物从顶部重新生成
  - 2 位速度选择提供 4 档游戏速度
  - 7 段数码管显示得分 (0-99)
  - 绿灯 = 游戏运行中，红灯 = Game Over
  - 蜂鸣器在 Game Over 时发声

四、分模块连线步骤

----------------------------------------------------------------------
模块 1: 时钟分频器 (产生 GAME_TICK 信号)
----------------------------------------------------------------------

  原理: 3 级 4 位寄存器 + 加法器级联，每级÷16。
        总分配系数 = 16×16×16 = 4096。
        MUX 从 CNT3 不同位选择输出，实现 4 档游戏速度。
        系统时钟 8Hz → 游戏时钟: 档0≈2Hz, 档1≈1Hz, 档2≈0.5Hz, 档3≈0.25Hz

  步骤 1.1: CNT1 (第 1 级计数器, 寄存器+加法器)
    1) ADD1(130,30).SUM → CNT1(200,30).D
       (起点: Adder 右侧 SUM 输出; 终点: Register 左侧 D 输入)
    2) CNT1(200,30).Q → ADD1(130,30).A
       (反馈: Register Q → Adder A)
    3) CNT_CONST(70,40) → ADD1(130,30).B
       (常数 1 → Adder B, 实现 +1 计数)
    4) CLK(80,40) → CNT1(200,30).CLK
       (系统时钟 → 寄存器时钟)
    5) EN_CONST(110,40) → CNT1(200,30).EN
       (使能 = 1, 始终计数)

  步骤 1.2: CNT2 (第 2 级计数器)
    1) ADD2(260,30).SUM → CNT2(330,30).D
    2) CNT2(330,30).Q → ADD2(260,30).A
    3) CNT_CONST(70,40) → ADD2(260,30).B
    4) CLK(80,40) → CNT2(330,30).CLK
    5) EN_CONST(110,40) → CNT2(330,30).EN

    注: CNT2 的进位逻辑由 Q[3] 自动控制。Register(4位)从 0xF 回绕到 0x0
        时自动产生进位，进位信号通过 CNT1.Q → CNT2 的数据路径传递。
        简化连线: CNT1.Q 的某位连接至 ADD2 的进位输入，或直接依赖
        Register 自动回绕。

  步骤 1.3: CNT3 (第 3 级计数器)
    1) ADD3(390,30).SUM → CNT3(460,30).D
    2) CNT3(460,30).Q → ADD3(390,30).A
    3) CNT_CONST(70,40) → ADD3(390,30).B
    4) CLK(80,40) → CNT3(460,30).CLK
    5) EN_CONST(110,40) → CNT3(460,30).EN

  步骤 1.4: MUX 速度选择
    1) CNT1(200,30).Q bit0 → SPD_MUX(560,60).数据输入0 (最快 16Hz)
    2) CNT3(460,30).Q 的 bit1 → SPD_MUX(560,60).数据输入1 (中速)
    3) CNT3(460,30).Q 的 bit2 → SPD_MUX(560,60).数据输入2 (慢速)
    4) CNT3(460,30).Q 的 bit3 → SPD_MUX(560,60).数据输入3 (最慢)

    提示: CNT3.Q 是 4 位总线。需要先用 Splitter(分线器) 将其分为 4 个
          单线，再分别连接到 MUX 各数据输入端。

    5) SPEED0(80,420) → SPD_MUX(560,60).选择0
    6) SPEED1(80,450) → SPD_MUX(560,60).选择1
    7) SPD_MUX(560,60).OUT → TICK_PIN(630,85) (输出游戏时钟信号)

----------------------------------------------------------------------
模块 2: 障碍物列源生成器 (产生"随机"列位置)
----------------------------------------------------------------------

  原理: 4 位寄存器 + 加法器，每次 TICK 递增 3。
        由于 4 位寄存器自动模 16 回绕，值在 0-15 间"随机"变化。

  步骤:
    1) OBS_SRC(200,140).Q → OBS_ADD(130,140).A (反馈)
    2) STEP3(70,160) → OBS_ADD(130,140).B (步进值 3)
    3) OBS_ADD(130,140).SUM → OBS_SRC(200,140).D
    4) TICK_PIN(630,85) → OBS_SRC(200,140).CLK (游戏时钟驱动)
    5) EN_CONST(110,40) → OBS_SRC(200,140).EN
    6) OBS_SRC(200,140).Q → SRC_PIN(350,150) (输出给障碍物列寄存器)

    注: TICK_PIN 在右侧 (x=630)，需要走长线到左侧 OBS_SRC (x=200)。
        布线路径: (630, 85) → 水平到 (630, 200) → 水平到 (200, 200) → (200, 210)
        或者直接用斜线 (Logisim 支持任意角度连线)。

----------------------------------------------------------------------
模块 3: 小车位置控制器
----------------------------------------------------------------------

  原理: 4 位寄存器存储小车列位置 (0-15)。
        两个比较器检测边界:
          - CMP_LO: pos > 0 → LEFT 可以移动
          - CMP_HI: pos < 15 → RIGHT 可以移动
        LEFT 按下时, 位置 -1 (模 16 下加 15 = 减 1)
        RIGHT 按下时, 位置 +1
        MUX 选择 +1/-1/0 加到当前位置

  步骤 3.1: 边界检测
    1) CAR_POS(200,250).Q → CMP_LO(360,230).A (当前位置)
    2) CAR_POS(200,250).Q → CMP_HI(360,280).A (同一信号分两路)
    3) CMP_LO_C(310,230) → CMP_LO(360,230).B (常数 0)
    4) CMP_HI_C(310,280) → CMP_HI(360,280).B (常数 15)

  步骤 3.2: 移动允许逻辑
    1) CMP_LO(360,230).GT → AND_L(450,230).输入1 (pos > 0)
    2) LEFT(80,120) → AND_L(450,230).输入2 (LEFT 按钮)
    3) CMP_HI(360,280).LT → AND_R(450,280).输入1 (pos < 15)
    4) RIGHT(80,190) → AND_R(450,280).输入2 (RIGHT 按钮)

  步骤 3.3: MUX 选择移动方向
    1) CONST_1(60,310) → MV_MUX(200,320).数据输入0 (+1)
    2) CONST_M1(60,340) → MV_MUX(200,320).数据输入1 (-1)
    3) CONST_0(60,370) → MV_MUX(200,320).数据输入2 (保持)
    4) AND_L(450,230).OUT → MV_MUX(200,320).选择0
    5) AND_R(450,280).OUT → MV_MUX(200,320).选择1

  步骤 3.4: 位置更新
    1) CAR_POS(200,250).Q → CAR_ADD(130,250).A (当前位置)
    2) MV_MUX(200,320).OUT → CAR_ADD(130,250).B (偏移量 +1/-1/0)
    3) CAR_ADD(130,250).SUM → CAR_POS(200,250).D (新位置)
    4) TICK_PIN(630,85) → CAR_POS(200,250).CLK (游戏时钟)
    5) EN_CONST(110,40) → CAR_POS(200,250).EN
    6) CAR_POS(200,250).Q → CAR_PIN(530,250) (输出)

  注: CAR_ADD 的 SUM 输出是 4 位值，自动模 16 回绕。
      当位置=0 时，LEFT 按下后 0+15=15 回绕到 15，但 AND_L 已禁止。
      当位置=15 时，RIGHT 按下后 15+1=16→0 回绕到 0，但 AND_R 已禁止。

----------------------------------------------------------------------
模块 4: 障碍物位置管理
----------------------------------------------------------------------

  原理: OBS_COL 寄存器存储障碍物的列位置，从 OBS_SRC 载入。
        OBS_ROW 寄存器 + 加法器追踪障碍物的行位置，从 0 计数到 15。
        当行 = 15 时，比较器发出 AT_BOTTOM 信号。

  步骤 4.1: 障碍物列
    1) SRC_PIN(350,150) → OBS_COL(200,480).D (从列源载入列位置)
    2) TICK_PIN(630,85) → OBS_COL(200,480).CLK
    3) EN_CONST(110,40) → OBS_COL(200,480).EN
    4) OBS_COL(200,480).Q → COL_PIN(530,480) (输出)

  步骤 4.2: 障碍物行
    1) OBS_ROW(400,480).Q → ROW_ADD(330,480).A (反馈)
    2) ROW_CONST(280,510) → ROW_ADD(330,480).B (+1)
    3) ROW_ADD(330,480).SUM → OBS_ROW(400,480).D (新行)
    4) TICK_PIN(630,85) → OBS_ROW(400,480).CLK
    5) EN_CONST(110,40) → OBS_ROW(400,480).EN
    6) OBS_ROW(400,480).Q → ROW_PIN(530,520) (输出)

  步骤 4.3: 到达底部检测
    1) OBS_ROW(400,480).Q → ROW_CMP(400,560).A
    2) CONST_15(350,590) → ROW_CMP(400,560).B
    3) ROW_CMP(400,560).EQ → BOT_PIN(530,580) (AT_BOTTOM 信号)

----------------------------------------------------------------------
模块 5: 碰撞检测
----------------------------------------------------------------------

  原理: 当障碍物到达底部 (AT_BOTTOM=1) 且列位置与小车相同 (COL_EQ=1) 时，
        碰撞发生 (HIT=1)。

  步骤:
    1) CAR_PIN(530,250) → COL_CMP(620,250).A (小车列位置)
    2) COL_PIN(530,480) → COL_CMP(620,250).B (障碍物列位置)
    3) COL_CMP(620,250).EQ → HIT_AND(720,300).输入1 (列匹配)
    4) BOT_PIN(530,580) → HIT_AND(720,300).输入2 (到达底部)
    5) HIT_AND(720,300).OUT → HIT_PIN(820,300) (碰撞信号输出)

----------------------------------------------------------------------
模块 6: 游戏状态机 (FSM)
----------------------------------------------------------------------

  状态定义:
    IDLE      = 00 (S1=0, S0=0)  — 等待开始
    RUNNING   = 01 (S1=0, S0=1)  — 游戏进行中
    GAME_OVER = 10 (S1=1, S0=0)  — 游戏结束

  状态转移:
    IDLE      → RUNNING   (START 按钮 & !S1 & !S0)
    RUNNING   → GAME_OVER (HIT 碰撞)
    RUNNING   → RUNNING   (!HIT, 保持)
    GAME_OVER → IDLE      (RST 按钮复位)

  步骤 6.1: 状态寄存器基础连接
    1) CLK(80,40) → FF_S1(700,60).CLK (系统时钟)
    2) CLK(80,40) → FF_S0(700,160).CLK
    3) RST(80,330) → FF_S1(700,60).CLR (复位清零)
    4) RST(80,330) → FF_S0(700,160).CLR
    5) EN_CONST(110,40) → FF_S1(700,60).EN (始终启用)
    6) EN_CONST(110,40) → FF_S0(700,160).EN

  步骤 6.2: 下一状态逻辑 — S1_next = HIT & S0
    (只有 RUNNING 状态(S0=1)下碰撞才进入 GAME_OVER(S1=1))
    1) HIT_PIN(820,300) → AND_S1(780,480).输入1
    2) FF_S0(700,160).Q → AND_S1(780,480).输入2
    3) AND_S1(780,480).OUT → FF_S1(700,60).D

  步骤 6.3: 下一状态逻辑 — S0_next = (START & !S1 & !S0) | (!HIT & S0)
    a) START 条件:
    1) FF_S1(700,60).Q → NOT_S1(580,400).IN
    2) NOT_S1(580,400).OUT → AND_START(620,400).输入1
    3) FF_S0(700,160).Q → NOT_S0(580,440).IN
    4) NOT_S0(580,440).OUT → AND_START(620,400).输入2
    5) START(80,260) → AND_START(620,400).输入3 (注: 可能需要3输入AND,
       或用2级AND级联)

    b) 保持 RUNNING 条件:
    1) HIT_PIN(820,300) → NOT_HIT(780,350).IN
    2) NOT_HIT(780,350).OUT → AND_KEEP(700,400).输入1
    3) FF_S0(700,160).Q → AND_KEEP(700,400).输入2

    c) 合并:
    1) AND_START(620,400).OUT → OR_S0(660,480).输入1
    2) AND_KEEP(700,400).OUT → OR_S0(660,480).输入2
    3) OR_S0(660,480).OUT → FF_S0(700,160).D

  步骤 6.4: 状态输出
    1) FF_S1(700,60).Q → S1_PIN(880,60)
    2) FF_S0(700,160).Q → S0_PIN(880,160)

  步骤 6.5: RUNNING LED (绿灯)
    1) FF_S1(700,60).Q → NOT_RUN(840,250).IN
    2) NOT_RUN(840,250).OUT → AND_RUN(880,250).输入1
    3) FF_S0(700,160).Q → AND_RUN(880,250).输入2
    4) AND_RUN(880,250).OUT → LED_RUN(980,250)

  步骤 6.6: GAME_OVER LED (红灯)
    1) FF_S1(700,60).Q → AND_GO(880,320).输入1
    2) FF_S0(700,160).Q → NOT_GO(840,320).IN
    3) NOT_GO(840,320).OUT → AND_GO(880,320).输入2
    4) AND_GO(880,320).OUT → LED_GO(980,320)

  注意: 上述 FSM 用了 3 输入 AND 门 (AND_START)。
        如 Logisim 中 AND 门只有 2 输入，请改为:
        - 先用 AND_A: START & !S1
        - 再用 AND_START: AND_A.OUT & !S0

----------------------------------------------------------------------
模块 7: 计分器
----------------------------------------------------------------------

  原理: 当障碍物安全通过 (AT_BOTTOM=1 且 HIT=0 且 RUNNING) 时得分 +1。
        个位 BCD 计数器 (SCORE1)，到 9 时进位到十位 (SCORE10)。
        两个 7 段数码管实时显示分数 (0-99)。

  步骤 7.1: 得分触发信号
    1) HIT_PIN(820,300) → NOT_HIT2(560,720).IN
    2) NOT_HIT2(560,720).OUT → AND_SCORE(620,720).输入1
    3) BOT_PIN(530,580) → AND_SCORE(620,720).输入2 (AT_BOTTOM)
    4) AND_SCORE(620,720).OUT → SCORE1(700,560).EN (使能个位计数)

  步骤 7.2: 个位计数器
    1) SCORE1(700,560).Q → SC1_ADD(620,560).A (反馈)
    2) SC1_CONST(580,580) → SC1_ADD(620,560).B (+1)
    3) SC1_ADD(620,560).SUM → SCORE1(700,560).D
    4) TICK_PIN(630,85) → SCORE1(700,560).CLK
    5) SCORE1(700,560).Q → DISP1(860,560) (7段数码管)

  步骤 7.3: 进位检测 (个位=9)
    1) SCORE1(700,560).Q → CMP9(560,680).A
    2) CONST9(510,680) → CMP9(560,680).B
    3) CMP9(560,680).EQ → SCORE10(700,640).EN (个位=9 时使能十位)

  步骤 7.4: 十位计数器
    1) SCORE10(700,640).Q → SC10_ADD(620,640).A
    2) SC1_CONST(580,580) → SC10_ADD(620,640).B (+1)
    3) SC10_ADD(620,640).SUM → SCORE10(700,640).D
    4) TICK_PIN(630,85) → SCORE10(700,640).CLK
    5) SCORE10(700,640).Q → DISP10(860,630) (7段数码管)

  步骤 7.5: 复位
    1) RST(80,330) → SCORE1(700,560).CLR
    2) RST(80,330) → SCORE10(700,640).CLR

----------------------------------------------------------------------
模块 8: LED 矩阵显示控制器
----------------------------------------------------------------------

  原理: 使用行扫描方式驱动 16×16 LED 矩阵。
        SCAN_ROW (0-15) 快速扫描每一行，系统时钟驱动。
        对于当前扫描行:
          - 如果 scan = 14 或 15 → 显示小车列的 LED
          - 如果 scan = obs_row → 显示障碍物列的 LED
          - 否则 → 该行全灭

  步骤 8.1: 行扫描计数器
    1) SCAN_ROW(200,620).Q → SCAN_ADD(130,620).A (反馈)
    2) CNT_CONST(70,40) → SCAN_ADD(130,620).B (+1)
    3) SCAN_ADD(130,620).SUM → SCAN_ROW(200,620).D
    4) CLK(80,40) → SCAN_ROW(200,620).CLK (系统时钟, 快速扫描)
    5) EN_CONST(110,40) → SCAN_ROW(200,620).EN
    6) SCAN_ROW(200,620).Q → LED_MATRIX(900,640).ROW (行地址)
       提示: LED Matrix 的 Row 输入是 4 位二进制行地址

  步骤 8.2: 行比较器
    1) SCAN_ROW(200,620).Q → CMP_14(400,620).A
    2) SCAN_ROW(200,620).Q → CMP_15(400,670).A
    3) SCAN_ROW(200,620).Q → CMP_OBS(400,720).A
    4) CST14(340,630) → CMP_14(400,620).B
    5) CST15(340,680) → CMP_15(400,670).B
    6) ROW_PIN(530,520) → CMP_OBS(400,720).B (障碍物行位置)

  步骤 8.3: 列数据生成
    1) CAR_PIN(530,250) → DEC_CAR(560,620).输入 (4位列→16位one-hot)
    2) COL_PIN(530,480) → DEC_OBS(560,700).输入

    然后将两个 Decoder 的输出组合:
    - 当 CMP_14.EQ=1 或 CMP_15.EQ=1: 选择 DEC_CAR 的输出
    - 当 CMP_OBS.EQ=1: 选择 DEC_OBS 的输出
    - 否则: 输出全 0

    提示: 使用 OR 门阵列将 CAR 列数据和 OBS 列数据组合。
          需要 16 个 2输入 OR 门 (或使用 MUX 选择)。

  简化方案:
    由于 Logisim 中 16 位 OR 门阵列较复杂，建议直接使用以下方法:
    - DEC_CAR 的每个输出位连接一个 OR 门的输入1
    - DEC_OBS 的对应输出位连接同一个 OR 门的输入2
    - OR 门输出连接到 LED Matrix 的对应列输入

    或者更简单的方法: 将 DEC_CAR 和 DEC_OBS 的输出直接连到 LED Matrix
    的 Col 输入 (需要合并)。因 Logisim 支持总线，可以使用 Splitter 或
    直接连 16 位总线。

  步骤 8.4: LED Matrix 连接
    1) SCAN_ROW.Q → LED_Matrix.Row (4位行地址)
    2) 组合后的列数据 → LED_Matrix.Col (16位列数据)

模块 9: 输出设备

五、全局复位总线

  RST 按钮 (80,330) 需要连接到所有寄存器的 CLR 引脚:

  ┌────────────────────────────────────────────────────────┐
  │ 从 RST(80,330) 连接到:                                  │
  ├────────────────────────────────────────────────────────┤
  │ CNT1(200,30).CLR     — 时钟分频器1                     │
  │ CNT2(330,30).CLR     — 时钟分频器2                     │
  │ CNT3(460,30).CLR     — 时钟分频器3                     │
  │ OBS_SRC(200,140).CLR — 障碍物列源                      │
  │ CAR_POS(200,250).CLR — 小车位置                        │
  │ OBS_COL(200,480).CLR — 障碍物列                        │
  │ OBS_ROW(400,480).CLR — 障碍物行                        │
  │ SCAN_ROW(200,620).CLR— 扫描行                          │
  │ FF_S1(700,60).CLR    — 状态寄存器1                     │
  │ FF_S0(700,160).CLR   — 状态寄存器0                     │
  │ SCORE1(700,560).CLR  — 计分器个位                      │
  │ SCORE10(700,640).CLR — 计分器十位                      │
  └────────────────────────────────────────────────────────┘

  布线方法:
    从 RST(80,330) 向右拉一条水平主线 (RST_BUS) 到 x=700 左右。
    然后从主线向上/向下分支到各个寄存器的 CLR 引脚。

六、游戏速度档位说明
================================================================================

  SPEED1 SPEED0 | CNT1 位 | 约分频比 | 游戏感
  ──────────────┼─────────┼─────────┼───────
             0      0   |  bit 0  |  /2      | 最快 (≈16Hz@32Hz时钟)
             0      1   |  bit 1  |  /4      | 快   (≈8Hz)
             1      0   |  bit 2  |  /8      | 中   (≈4Hz)
             1      1   |  bit 3  |  /16     | 慢   (≈2Hz)

  注: 实际分频比取决于时钟分频器的级联设计。
      以上为近似值，实际游戏速度以 Logisim 仿真为准。

七、测试与验证步骤
================================================================================

  1. 打开 new.circ 在 Logisim-evolution 中

  2. 设置仿真频率: "模拟" → "仿真频率" → 32 Hz

  3. 初始状态检查:
     - 7 段数码管显示 00
     - 绿灯灭，红灯灭
     - LED 矩阵无显示 (或全暗)

  4. 按 START 按钮:
     - 绿灯亮起 (RUNNING 状态)
     - LED 矩阵上应能看到小车 (底部某列)
     - 障碍物从顶部开始下落

  5. 按 LEFT/RIGHT 按钮:
     - 小车应在底部左右移动
     - 到达最左边时再按 LEFT 不动
     - 到达最右边时再按 RIGHT 不动

  6. 躲避障碍物:
     - 障碍物到达底部且未碰到小车 → 分数 +1
     - 7 段数码管实时更新

  7. 碰撞测试:
     - 让小车对准障碍物的列
     - 障碍物到达底部 → 红灯亮，Game Over
     - 蜂鸣器发声

  8. 按 RST 按钮:
     - 分数归零
     - 状态回到 IDLE
     - 所有 LED 灭

  9. 速度切换:
     - 修改 SPEED0/SPEED1 的值 (用 Poke Tool 点击)
     - 观察障碍物下落速度变化

================================================================================
八、常见问题排查
================================================================================

  Q: 小车不动?
  A: 检查 CAR_POS 寄存器的 EN 是否接高电平;
     检查 TICK 信号是否正常到达 CAR_POS.CLK;
     检查 LEFT/RIGHT 按钮的接线。

  Q: 障碍物不下落?
  A: 检查 OBS_ROW 寄存器的 EN 和 CLK 信号;
     检查 ROW_ADD 的接线 (反馈 + 常数1 → 行 +1)。

  Q: 碰撞不检测?
  A: 检查 COL_CMP 的两个输入 (CAR_COL 和 OBS_COL);
     检查 AT_BOTTOM 信号 (ROW_CMP.EQ 输出);
     检查 HIT_AND 的输出是否连接到 FSM。

  Q: 分数不更新?
  A: 检查 AND_SCORE 触发信号;
     检查 SCORE1 寄存器的 EN 是否连接正确;
     检查进位逻辑 (CMP9.EQ → SCORE10.EN)。

  Q: LED 矩阵不显示?
  A: 检查 SCAN_ROW 是否在计数;
     检查 Decoder 输入和输出;
     确认 LED Matrix 的 Row 和 Col 输入正确连接。

  Q: 仿真出现红色/橙色线?
  A: 表示信号冲突或多路驱动。检查是否有多个输出连接到同一节点。
     使用三态缓冲器或 MUX 避免冲突。
